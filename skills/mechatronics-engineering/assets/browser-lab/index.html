Bode response

L = C × G

How the loop changes sinusoid amplitude and phase. At 0 dB the loop magnitude is one; phase near −180° can turn intended correction into reinforcement.

Crossings are interpolated over the displayed finite frequency range. All detected crossings are reported. Missing crossings are “not found”; they are not automatically infinite margins.

The encirclement rule

Use clockwise-positive net encirclements N of −1 for the complete mapped contour. Then Z = P + N, where P counts right-half-plane open-loop poles and Z counts right-half-plane closed-loop poles.

The ideal plant here has P = 0. An integral pole at s = 0 is on the contour boundary, not in P; it needs an indentation and limit treatment.

No encirclement verdict is inferred from this finite trace. The separately displayed pole calculation evaluates the ideal continuous characteristic polynomial directly.

START HERE

A useful first experiment

  1. Run the defaults and watch the mass approach the target.
  2. Set Ki to zero. The proportional controller needs position error to produce the spring’s holding force; the final position stays below the target.
  3. Restore Ki. Integral action can supply that holding force after the position error has reduced.
  4. Reduce the force limit to 2 N. For a 1 m target and 4 N/m spring, the required 4 N exceeds the actuator limit. Tuning cannot overcome missing force.
  5. Increase Ts to 0.2 s. The sampled implementation changes, while the continuous plots stay the same. That gap is why digital stability needs its own analysis.
  6. Adjust g and compare the poles, time response, and frequency response. Then vary mass or stiffness to test model sensitivity.
WHAT THE MODEL MEANS

Equations and assumptions

m·ẍ + b·ẋ + k·x = u + d

The plant is one linear translational degree of freedom, an ideal spring, and viscous damping. Initial position and velocity are zero. Disturbance d is a constant force applied from t = 0.

The time controller uses u = clip(g[Kp(r−x) + I − Kd·v̂], ±Fmax). Integral update is conditional: it freezes when the error would drive an already saturated actuator further into saturation. The derivative estimate uses an exponential low-pass filter on sampled position differences.

The continuous derivative-on-measurement architecture has the same characteristic feedback denominator as C(s) above, but a different setpoint numerator from derivative-on-error. The Bode plot is the feedback loop L, not the setpoint transfer function.

Stored energy is ½mv² + ½kx². Its rate is (u+d)v − bv²: the controller and disturbance can add energy, and damping dissipates it.

NUMERICAL EVIDENCE

What you can conclude

The core computes polynomial roots, complex frequency response, sampled controller updates, RK4 motion, and 3D forward kinematics. The render loop consumes a separate simulated clock. Frame rate and playback speed do not define the integration step.

Time data are logged at controller sample instants; chart drawing may decimate only the display. Exports contain the complete logged run. Plot hover shows a nearby computed sample, not an exact analytic point. Margins are finite-grid estimates and root locations have floating-point numerical error.

Run stops at the requested duration (rounded up to the next sample). Extreme excursions stop the numerical experiment. A stable continuous pole result does not validate the sampled or saturated implementation.

These are illustrative model results. No physical system, material selection, manufacturing process, safety function, sensor chain, or hardware controller has been commissioned by this page.

EXTEND THE LAB

Turn a problem into a model

  1. State the measured output, command, units, operating envelope, and acceptance criteria.
  2. Replace the plant derivatives in math.js with traceable equations and parameters. Add the new states to the export schema.
  3. Write conservation, equilibrium, limiting-case, convergence, and known-solution checks before using the model for decisions.
  4. Keep the simulation clock independent of rendering. Add sample timing, saturation, noise, delays, and actuator dynamics explicitly when needed.
  5. For 3D dynamics, introduce mass and inertia tensors, joint forces, constraints, contacts, and a suitable solver. Changing geometry alone does not add dynamics.
  6. Compare predictions against measured data, document differences, and validate the intended operating range.
